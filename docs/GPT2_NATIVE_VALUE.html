Does the gate effect depend on zero source values?

GPT-2 research checkpoint, 21 October 2026. T19 in the continuing super-weight investigation. Repository.

The effect survives in intact GPT-2

The layer-10 gate result does not require zero source values on this panel. Applying the frozen leading-direction removal to intact GPT-2 worsens Wiki validation loss and improves loss on Utilitarianism, Ethics and optimizer code. All eight native-model corpus/start intervals exclude a perplexity ratio of one. This rejects the explanation that these gains can only be a repair of damage caused by source-value zeroing. It does not establish a universally beneficial edit, a unique direction, or better generated text.

Values modify the effect without creating its sign

Source values still matter. For natural-start code, the removal effect is −0.018595 nats per target at the intact boundary and −0.023382 at the all-zero boundary. Their paired difference is −0.004787 [−0.007191, −0.002088]. The BOS endpoint difference is −0.004633 [−0.006304, −0.002739]. At otherwise intact settings, upstream L4–9 zeroing changes the code effect by −0.003866 natural and −0.003832 BOS; local L10 zeroing changes it by −0.000689 and −0.000670. Each of those four intervals excludes zero. The downstream L11 differences are smaller and have intervals spanning zero. These are controlled finite effect differences, not percentages of a mediated pathway.

Across all settings of the other factors, code's eight upstream interaction intervals are negative; seven of eight local intervals are negative. Wiki factor intervals all span zero. Other sources contain smaller but detectable interactions, including downstream changes on Ethics. Thus the sign's persistence does not imply that source values or the altered upstream state are functionally irrelevant, or that all three factors are interchangeable. All first-, second- and third-order contrasts remain in the numerical record.

The causal-order checks make the local comparison interpretable. At a shared upstream state, changing the local source V leaves incoming L10 Q/K, non-source V and the gate coefficient exactly unchanged; changing L11 leaves the delivered L10 state unchanged. The direct native-minus-zero context delta matches the value contribution identity within the frozen bound. Later network computation remains live. These checks distinguish a direct value contribution from a changed incoming computation; they do not identify a minimal circuit or make later loss responses additive.

Loss gains are not faithful replacement

Native PC1 removal retains only 95.88–98.28% argmax agreement with intact GPT-2 across the eight groups, with mean reference-to-trial KL 0.003225–0.004175 nats per scored query. Improved book/code loss therefore coexists with changed predictions and distributions. No generation experiment, speedup or output-preserving compression is established.

The numerical controls also have a practical limit. Delta and older scaling arithmetic passed the prospectively frozen context and loss criteria, but their full hidden states and logits are not byte-identical. The observed mass can reach one and slightly exceed it by FP32 rounding; no clipping was introduced. The complete raw states cover eight predetermined L10 snapshots on one Wiki input. Other conditions retain runtime comparisons, diagnostics and fingerprints, not full independent attention reconstruction.

What was intervened on

This is a GPT-2 follow-up in the broader super-weight investigation. All layer numbers are zero-based. The pinned checkpoint is openai-community/gpt2, revision 75e09b43581151bd1d9ef6700faa605df408979f, evaluated in FP32 with the recorded SDPA backend. The prescribed interventions do not edit parameters. Both completed recovery segments passed before/after parameter checks; the interrupted original process lacks its final check, as detailed below. Each forward executes exactly 512 physical positions with caching disabled.

Three independently controlled source-value boundaries form eight settings:

The source is token position zero, across all heads. 000 is intact GPT-2; 111 has source values zeroed in layers 4–11. Native values come from each condition's live trajectory, not a clean donor. The intervention directly changes only the specified V slices. Later queries, keys and non-source values can respond to the altered computation.

At L10, every boundary has a baseline, an exact current control, removal of the frozen leading gate direction, and a matched orthogonal change. The center and directions are the fresh four-Wiki calibration F from Report14; no calibration or direction was fitted to these new evaluation passages. This tests transfer of that particular fitted operation across value boundaries. It does not test the best possible native-model calibration.

For query q>0, let b be the 12-head difference between non-source log-sum-exp attention score and source score, and let a be the summed reconstructed non-source softmax probability. Let m be the conditional non-source value mixture and v0 the live source value. With frozen center alpha and unit leading direction u, the removal coefficient is s = (b - log(q) - alpha) dot u. Removal changes b to b - s*u; the control changes it to b - s*v, for a fixed orthogonal unit vector v. These changes have matched gate-logit norm at their own incoming state. Their context-vector norms are not matched.

The delivered attention context is c_actual + (sigmoid(b_target) - a) * (m - v0). The conditional mixture is computed from a separately normalized non-source distribution. This avoids division by a tiny non-source probability mass. The gate edit leaves query zero unchanged. Source-value zeroing can itself change query zero relative to intact GPT-2. An exactly unchanged gate uses an exact no-change bypass, with no near-zero threshold, clipping or epsilon.

Two additional arms at 111 implement the older scaling arithmetic on the same local state. They are an arithmetic bridge within this study, not a second execution of the older explicit-mask protocol. Before execution, the reviewed hard limits were context maximum error 1e-4, all scored target-loss differences 1e-3 nats, and absolute passage-mean loss difference 1e-5 nats. Current, source, incoming/delivered causal-order fingerprints and suffix controls require exact equality. The separate direct local-value delta identity uses the prospectively bounded 1e-4 reconstruction criterion. Any hard failure stops the accepted batch and preserves the compared states; no outcome-based input exclusion or tolerance increase is allowed.

This implementation computes the native attention context and diagnostics before applying the defined change. It is a causal probe, not a faster model or a demonstrated replacement of the upstream computations. Runtime savings and faithful generation are not established by its loss comparisons.

Evaluation, uncertainty and causal scope

Sixteen fresh passages comprise four each from Wiki validation, Utilitarianism, Ethics and optimizer code. A deterministic selection and rejection ledger excludes prior evaluation spans and complete calibration buffers. Each passage has its natural first token and a paired BOS replacement of token zero only. Tokens are neither inserted nor retokenized. This isolates the replacement on the same suffix, but the natural identities are not balanced across sources or drawn from a defined token population. The passages are held out from this investigation's calibration and prior evaluation exposures; overlap with GPT-2's original pretraining is unknown.

Each boundary's primary effect is its intervention NLL minus its own baseline NLL, scoring targets 2–511. Effects relative to intact C, KL and argmax agreement are reported separately. Early targets 2–127 and later targets 128–511 are secondary views of the same forward, not different context-length experiments. Every scientific condition has a second 512-position forward with tokens 128–511 rotated. All unchanged-prefix outputs and diagnostics must agree exactly. Direct unhooked and historical writer-identity anchors are checked on the natural first passage from each source.

The 64 predeclared contrasts include within-boundary effects, removal minus orthogonal control, endpoint effect differences, all controlled single-factor interactions, and second- and third-order factorial interactions. They are finite intervention contrasts. They are not additive mediation percentages, unique pathways, or counts of causal mechanisms. Common-state checks separate the direct local V change from an upstream change in the gate computation; later network responses remain live.

Paired bootstrap intervals use four passage clusters per source, 2,000 draws and seed 20261021. The same resampled passage indices are reused across arms and paired starts. Intervals condition on the one frozen F calibration. The passages are deterministic rather than a random population sample, and the many contrasts and score views are correlated. There is no adjustment for multiple comparisons or estimate of population calibration uncertainty. Loss improvement does not establish output fidelity or generation quality.

Attribution

The original Super Weight paper establishes single-weight sensitivity and super activations. Massive Activations, including Appendix B.4, studies implicit attention biases and explicit alternatives. Fu et al. derive related implicit gate algebra, and the GPT-2 attention-sink study tests query bias and positional/key structure causally. The allocation/value identity, sigmoid gate and PCA procedure are established context. This batch adds a controlled comparison of one frozen fitted operation across native and zero-source-value boundaries, with explicit numerical and matched controls. It does not claim discovery of sinks, a universal super-weight mechanism or priority for this exact factorial. The repository's broader novelty comparison retains the preceding primary-source review and access limitations. The earlier GPT-2 candidate did not reproduce OLMo's catastrophic single-weight loss effect. These GPT-2 gate/value results concern a related computation in this checkpoint; similar activation sizes or gate effects do not establish transfer of the original OLMo pulse mechanism.

python -B scripts/audit_native_value_results.py

This checks the exact 83-file numerical release and recomputes all 3,264 window rows, 816 summaries, 1,536 contrasts, 768 paired-start contrasts and 3,276 norm rows from the exported arrays. The same 2,000-by-four bootstrap indices and seed 20261021 are used. On the author machine this took 14.994 seconds with 0.102 GiB peak RSS. All loss/KL/agreement statistics, intervals and contrasts matched exactly. The largest norm-aggregate difference between the NumPy and original Torch reductions was 7.106e-15, below the unchanged independent policy of 1e-10 absolute plus 1e-12 relative for norms. This is numerical reanalysis of the restricted export, not another pretrained execution or a rerun of the private full-attention/readout audit.

results/gate_native_value/ contains 32 NPZ/JSON input pairs, aggregate analysis, scalar controls, sanitized audit views and explicit interruption provenance: 83 files, 244,621,310 bytes, including 41,632 numeric arrays. The export's export.json SHA256 is 13b21a7c807447bd6b6a831dd75a8847f75ddef14ea35866d6fc2d0bb7b41e13. It preserves per-target loss, KL, agreement and norm arrays. It excludes input and prediction token IDs, source text, weights, QKV, mixtures/contexts, hidden states, full-vocabulary readouts and full per-query gates. Those omissions prevent reconstruction of those private tensors from the public package; their original hashes remain commitments rather than a replacement for the unavailable contents. Original private evidence remains stored locally.

The model path uses the immutable 35-file package under results/gate_native_value_reproduction/. It contains the frozen scientific source closure, safe selection/history metadata and exactly three original small T18 reference files: aggregate calibration manifest, maps and directions. No old T18/T11 model experiment, calibration refit or Llama loading is required. Historical exposure and exclusion commitments are inherited attestations; preparation does not newly audit unavailable historical streams.

Source and tokenizer hashes are in the package's metadata/data_manifest.template.json. The checkpoint is openai-community/gpt2 revision 75e09b43581151bd1d9ef6700faa605df408979f, FP32. The original runtime was Python 3.12.3, Torch 2.11.0+cu130, Transformers 4.57.6 and NumPy 1.26.4. Weights and source corpora are obtained separately under their own terms. The repository guide provides source links and the configuration keys.

python -B results/gate_native_value_reproduction/experiments/pulse_transfer/native_value_portable_draft.py rebuild \

python -B results/gate_native_value_reproduction/experiments/pulse_transfer/native_value_portable_draft.py stage-replay \
  --config inputs.local.json --package results/gate_native_value_reproduction \
  --inputs .reproduce-native-inputs --out .reproduce-native-model

These commands prepare a later run; they launch zero model forwards. The stage's preparation record supplies the exact model command. Rebuild rechecks all 382 candidates, 366 rejections and 16 accepted windows, canonical token bytes, BOS identity and historical-scan commitments. Stage independently rechecks the reconstructed inputs and changes only the runner's six input-file hashes. Output-containment guards reject attempts to create private outputs inside the immutable package or replay inputs. Bytecode creation is disabled. The tokenizer-only reconstruction and staging were rehearsed locally; a second 2,184-forward pretrained replay has not been performed.

A fresh successful model run performs 2,184 scientific forwards, with its own source/parameter/precision guards. It does not reproduce the original lost process or retroactively establish its missing final guards. On this machine the two recovery segments took about four and three-and-a-half minutes. Allow an 8 GiB GPU, 16 GiB host memory and at least 2 GiB free reserve in addition to the checkpoint, dependencies, source files and new evidence. Timing is hardware specific. Run one model worker; keep CPU review jobs near 3 GiB or less.
