# T18 standalone reproduction proposal

Status: **design only, awaiting review**. This document proposes separate preparation and reproduction tools; it does not change the frozen T18 runner, authorize a model launch, or claim a completed replay. Inspection used source code and saved JSON/ZIP metadata only: zero tokenization, selection, calibration fits, model forwards or GPU activity. The accompanying [contract evidence](review/gate_wiki_replay_contract.json) records the observed source hashes, canonical input identities and all 20 window hashes. Its source hashes describe the inspected snapshot, not a replacement for the parent's final launch freeze.

## Intended route

An outside researcher should need a pinned local GPT-2 checkpoint/tokenizer, the seven source files used by the 20 T18 windows, and either a validated original M8 calibration reference or an explicit eight-forward calibration-only rebuild. No UIT knowledge, Llama/OLMo weights, previous model-study runs, original private directories or token arrays shipped in the repository are required. Source acquisition remains manual and must produce the pinned bytes; no download, credential change or publication occurs in these tools.

Proposed new files are `prepare_wiki_calibration_replay_inputs.py`, `reproduce_wiki_calibration.py`, and a numerical comparator. Default preparation performs zero model forwards. An explicit execution option runs exactly **1,548 T18 forwards**: four fresh calibration, 776 main/anchor and 768 suffix forwards. The separate M8 bootstrap adds eight only when needed, for **1,556 total**, and must never invoke the 1,352-forward earlier gate study. Preserve every attempt in a new directory; no automatic retries, resume, replacement calibration or deletion of prior results.

With an existing reference, validate original M8 raw/maps/spectra/token/input identities, map tensor digest, checkpoint revision/hash, parameter closure and the actual reference manifest. Accept only the reviewed original calibration provenance or the reviewed eight-forward rebuild provenance. Their operation ledgers have different known hashes; do not fabricate original operation counters to make them appear identical. The exact expected hashes are in the contract evidence.

W_old4 is fitted from `wiki_test__0` through`wiki_test__3` of this M8 raw reference using the frozen four-passage fitter, threads4 and fixed algorithm. Require digest `e59fab6ed96e92d34a3286680b989f8ca12608edee7923baaf088f5d1b40573d`. M8 stays unchanged. Four new W_fresh4 forwards and its fit remain inside T18. No recalibration/domain substitution is permitted when a strict reference fails validation.

The repository already has a usable eight-forward route: `scripts/run_gate_study.py --prepare-only` stages metadata, then `rebuild_gate_calibration.py` performs only eight calibration forwards. **Its current preparation still needs the pinned Llama tokenizer/config (no Llama weights), and also stages old evaluation metadata.** This is an existing fallback, not a GPT-2-only bootstrap, and the guide must say so. Never run `run_gate_study.py` without `--prepare-only` for this route, because that would also execute an older study.

To make the complete T18 route GPT-2-only, propose a separate prepared-input calibration bootstrap. Export a sanitized template of the original eight M8 calibration records and excluded buffers, preserving the original GPT-2 development and Llama-calibration manifest hashes as historical commitments. Reconstruct these eight inputs from pinned Wiki-test/Hume using GPT-2, recover local first-token IDs, and require the canonical M8 input JSON/token hashes. Then a new, independently reviewed eight-forward wrapper reuses the exact calibration hook, collection, fitter and precision policy from `rebuild_gate_calibration.py`, bypassing only old metadata preparation and unused evaluation preparation. Do not edit that frozen original script. Record the new bootstrap source identity/kind truthfully and require all canonical numerical outputs; reference validation must explicitly recognize the reviewed new provenance rather than passing it off as the old rebuild. This new bootstrap is a separate implementation/review prerequisite, not already delivered by this proposal.

## Wrapper, comparison and resource gates

Stage source basenames and pins from the final source inventory. Inspection found30 T18 `SOURCE_NAMES` entries; their union with the reviewed eight-forward rebuild is33 local files and already closes all local Python imports. Add new preparation/wrapper/comparison/bootstrap sources and their dependencies explicitly. Do not copy an unbounded research directory. Include the two small pinned `gpt2_run` manifest/selection records because the runner checks the selected L2/row447 metadata and checkpoint identities; no old raw selection tensors are required. Keep original helper scripts as provenance, but never execute their history-reading entrypoints. The runtime-safe `gate_direction_geometry.py`/`gate_factorial_algebra.py` dependencies must remain present; the old preparation modules must not be imported into the GPU subprocess in a way that hides CUDA.

Default preparation should have a measured64MiB staging allowance and retain at least2GiB free. It loads tokenizer/config only, creates a private config with caller-supplied local paths, runs zero forwards, and records no fabricated model-load facts. An explicit execute branch rechecks checkpoint/source/input hashes and calls only the staged T18 runner and CPU analyzer. Preserve the current176MiB normal/48MiB failure limits and2GiB reserve, including the per-group growth checks; account for staging bytes before launching. Do not copy model weights or old raw experiment directories. Review CPU jobs stay below3GiB; production resource limits remain those of the approved runner. Wrapper states distinguish prepared, execution requested, child failed/unknown, completed, and numerically compared. On a subprocess failure or uncertain return, inspect the child manifest before reporting counters; absence means unknown, not zero or completed.

The later comparator must compare actual deterministic numerical contents, not merely copied manifests: all776 main per-target records,768 suffix arrays, four fresh calibration raw bundles, O/F/M maps/directions/geometry, affected-layer norms, closure/fingerprint records, the11 raw snapshot/readout states, and all analyzer estimands/uncertainty. Compare portable source/metadata bindings separately. Same-environment exact equality is the initial target; cross-device drift must be reported without silently changing canonical maps or tolerances. A successful local run is not an independent external replication or a confirmed match until this comparison passes.
